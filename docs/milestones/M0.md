# M0. Project skeleton

Model: sonnet | Time: 1 to 2 days
Read first: docs/design.md (Repo layout)

## Why
Every later step needs a Postgres set up for logical replication, started the same way every time.

## How it works
wal_level=logical makes Postgres record enough in the WAL to rebuild row changes. The default does not.

## Task
- Create the Go module and the folder layout, with empty packages and doc comments.
- docker-compose.yml: Postgres 17, wal_level=logical, max_replication_slots=4, max_wal_senders=4.
- db/init.sql creates:
  - customers(id bigint primary key, name text, city text)
  - orders(id bigint primary key, customer_id bigint, status text, amount numeric(12,2), created_at timestamptz)
  - dv_heartbeat(id int primary key, seq bigint) with one row
  - REPLICA IDENTITY FULL on all three; publication deltaview_pub for them.
- Makefile targets from CLAUDE.md. GitHub Actions workflow running make check.
- No engine code.

## Definition of done
make up works. SHOW wal_level prints logical. CI is green.

## Explain it back (for the human)
- Why wal_level=logical? Lower levels do not record enough to decode row changes.
- What does REPLICA IDENTITY FULL cost? Every update and delete writes the whole old row to the WAL.
