# M2. Types and Z-sets

Model: opusplan; review with opus | Time: week 1 to 2
Read first: docs/design.md (Key types, State key layout), docs/testing.md (Z-set laws), docs/concepts.md section 2

## Why
Every operator speaks Z-sets. A bug here poisons everything above it.

## Task
- internal/types: Value, Row, canonical order-preserving Encode and Decode.
- internal/zset: Add, Merge, Negate, iteration in key order.
- Requirements: equal rows encode to identical bytes; numeric 1.0 equals 1.00; text '1' differs
  from integer 1; NULL differs from text 'NULL'; composite encodings are self-delimiting.
- Property tests with testing/quick and a fuzz test: round trip, ordering, and the Z-set laws.

## Definition of done
Property tests run thousands of random cases with no failure.

## Known traps
- Using fmt.Sprint(row) as a map key (ambiguous).
- Decimals with different scale that are equal in value.

## Explain it back (for the human)
- Why can a weight exceed 1? SQL tables are bags; duplicates are allowed.
- Why a canonical encoding? Rows are map keys and store keys. Two encodings of one row would count as two rows.
