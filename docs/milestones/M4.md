# M4. Aggregation

Model: opus, effort high, whole session | Time: week 3 to 5
Read first: docs/concepts.md section 5, docs/design.md (Operator, state.Tx, State key layout)
Do COUNT/SUM/AVG and MIN/MAX in separate sessions.

## Why
Aggregates are what most real views are for.

## Task
- Session 1: Aggregate operator for GROUP BY with COUNT(*), COUNT(col), SUM, AVG, following
  .claude/rules/operators.md, including every NULL rule and the one-row rule for no GROUP BY.
  State under the a/ prefix.
- Session 2: MIN and MAX with an ordered multiset per group under the x/ prefix.
- Add tester views: orders per status; SUM and AVG of amount per customer_id; MIN and MAX of
  amount per status; a global COUNT and SUM with no GROUP BY.
- Extend the workload: rows moving between groups, deletes that empty a group, NULL amounts.

## Definition of done
50 seeds pass. Mutation check: make MIN ignore deletes; the tester must fail. Then revert.

## Known traps
- SUM of an all-NULL group returning 0.
- Groups not removed at count 0.
- AVG computed in floats.
- No row for an empty global aggregate.

## Explain it back (for the human)
- Why is aggregation not linear? A group's output depends on all its rows together.
- What happens when the current MIN is deleted? The multiset gives the next smallest in one seek.
- What does MIN cost? Memory proportional to distinct values per group.
